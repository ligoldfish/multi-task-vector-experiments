**1．研究究竟要回答什么**

研究问题是：在同一个语言模型中，为不同任务学到的干预表示，是否含有可以在其它任务上发挥作用的共同成分？如果存在，这种共同成分能否帮助组合任务，以及完全没有参与结构构建的新任务？

例如，为数学题训练一个任务向量，再把它用到逻辑题上。此时依然给模型逻辑题和逻辑任务指令，只把内部干预从逻辑向量换成数学向量。如果逻辑准确率提高，才观察到了“数学任务表示对逻辑任务的正迁移”。它不意味着模型被要求先做数学，也不意味着两个向量只要接近就一定共享推理能力。

可以把模型比作已经具备许多技能的工作系统。任务向量是一种学出来的调节方式：LTV 调节某一时刻的内部状态；LoDA-MT 调节注意力计算的权重。实验先验证调节是否有效，再拆开调节量，检查哪些部分能跨任务起作用。这里的“能力成分”是需要通过干预支持的操作性解释，不能仅凭几何形状命名为某种独立、完整的认知能力。

原文不预设数学和逻辑一定一组、翻译和改写一定一组。得到单组、不同分组、不稳定分组、负迁移或没有共享收益，都应被保留。若小模型、小样本、固定层位下没有效果，结论也应限定在这个实验设置内。

本项目拟贡献的是排除格式/标签混淆后的功能共享证据、严格留出验证、两种表示空间中任务关系的一致性。LTV 已研究相似性、迁移和组合；LoDA 已有 General/Isolated 设计，不能把重复这些操作本身当成新贡献。[LTV 论文](https://arxiv.org/abs/2509.24169v3)、[LoDA 论文](https://arxiv.org/abs/2603.00191v4)。是否具有充分新颖性仍需结合完整相关工作和实际结果判断。

**2．完整证据链与结论边界**

| 证据层次 | 实际检查 | 能支持什么 | 仍不能单独证明什么 |
|---|---|---|---|
| E1 有效性 | 正确任务干预超过基座、随机同范数和未训练初始化 | 表示包含对本任务有用的信息 | 跨任务共享 |
| E2 几何 | cosine、实际更新子空间夹角、跨 seed 稳定性 | 表示关系具有一定稳定结构 | 相似部分具有功能 |
| E3 迁移 | 源任务表示作用于各目标任务 | 有方向的跨任务功能关系 | 效果来自哪一个成分 |
| E4 成分干预 | shared-only、residual-only、重建、删除 shared、随机同秩 | 提取成分确实影响任务表现 | 已实现有益的任务组合 |
| E5 组合 | 与相加、平均、调权、范数匹配比较 | 规定组合评测上的收益 | 未见任务泛化 |
| E6 留出 | 排除一个任务后重建全部结构；另测 SAMSum | 不依赖目标任务调参的迁移收益 | 超出所测模型、任务和规模的普遍结论 |

这里最容易发生的逻辑跳跃是“相似→共享能力”“低秩→能力可分解”“同一个 General 子空间→自然共享”。三者都不成立，必须用后续功能对照补证据。

**3．固定模型、任务和数据预算**

主设置为 `Qwen/Qwen3-1.7B`、BF16、`enable_thinking=False`、greedy decoding。模型配置确认为 28 层、hidden size 2048、16 个 query heads、8 个 KV heads、head dimension 128。[官方配置](https://huggingface.co/Qwen/Qwen3-1.7B/blob/main/config.json)。关闭特殊 thinking 模式，不等于删掉 GSM8K 训练目标中的解题过程；数学仍需监督完整解题过程和答案。

| 任务 | 原文指定数据/适配 | 主指标 | 补充信息 | 最大新生成 tokens |
|---|---|---|---|---:|
| 数学 | GSM8K；问题→完整解题过程和答案 | 最终答案准确率 | 提取失败率、截断率 | 512 |
| 逻辑 | ProofWriter；深度 0–3 | True/False/Unknown 准确率 | 分深度、分标签表现 | 32 |
| 翻译 | IWSLT2017；英语→德语 | chrF++ | BLEU | 256 |
| 改写 | QQP 正例；问题一→等义问题二 | iBLEU | 语义保持、复制率 | 128 |
| 代码生成（扩展） | MBPP | 一次生成通过全部测试的比例 | 超时、解析失败、截断率 | 512 |
| 代码修复（扩展） | MBPP 正确程序→经验证错误程序 | 修复后通过全部测试的比例 | 错误类型和未修复比例 | 512 |

四个 MVP 任务各有训练 512、调参 128、结构发现 128、最终测试 256 条；前 768 条来自官方训练划分，最终 256 条来自独立且有标签的官方评测划分。正式确认扩大到 1000 条或完整可用评测集。训练先 seed 17，通过有效性检查后加 29、43；固定样本 ID 应跨路线、跨训练 seed 复用，不能同时改变数据和初始化后把变化混为 seed 稳定性。

四份数据的职责必须分开：训练集学 v/B；调参集选 checkpoint 和干预强度；发现集决定秩与任务结构；最终测试集确认已锁定关系。发现集不替代训练集或调参集，测试集不参与任何候选选择。

防泄漏要求：

- ProofWriter 按 theory 分组，保证同一理论的不同问题不跨集合。三标签任务需要包含 Unknown 的 OWA 配置；“深度0–3”需明确是D3数据整体还是按问题深度筛选。Unknown 未必具有有限证明深度，不能用简单数值过滤把它删掉；同时锁定深度和标签构成。[原论文](https://aclanthology.org/2021.findings-acl.317.pdf)。
- QQP 按重复问题连通组分组，同时处理重复问题 ID/文本。若使用 GLUE QQP，其 test 没有公开标签，应使用有标签的官方 validation 正例作为最终评测候选，而不是把无标签 test 当作评测集。跨官方划分重复群组要显式处理，不改写其官方来源。[官方 QQP 处理器](https://github.com/huggingface/transformers/blob/main/src/transformers/data/processors/glue.py)。
- Code Generation/Repair 按原始程序 ID 联合划分。同一道 MBPP 题的正确程序、错误变体和修复目标必须留在同一集合；不能靠变体扩增得到虚假的独立样本数。
- 两路线使用同一份过滤后样本清单、prompt、target 和评测输入。不能各自随机采样。
- 超长训练答案不能截断后继续使用。建议先按已锁定规则构建合格样本池，再完成分组与固定采样；不足指定数量应报告不足，不静默更换来源或混入测试数据。

MBPP 扩展有明确容量缺口：官方完整配置 train 374 条，按文档取 300 条训练后仅余 74 条，无法再从 train 划出两个互斥的 128 条集合。[官方数据卡](https://huggingface.co/datasets/google-research-datasets/mbpp/blob/main/README.md)。因此 512/128/128/256 是 MVP 协议，不能机械套用代码任务；扩展集大小和来源需要独立锁定。

IWSLT2017 还需要核验具体数据配置、官方年份/评测 split 和加载方式。只锁 `transformers=4.51.3` 不足以固定数据行为；必须同时固定 datasets、数据 revision、原始文件和转换流程。不得用相近翻译数据集替代 IWSLT2017。[datasets 4.0 迁移信息](https://github.com/huggingface/datasets/releases/tag/4.0.0)。

**4．两条表示路线怎样实现同一个研究问题**

| 项目 | LTV | LoDA-MT |
|---|---|---|
| 表示空间 | 模型的 activation/residual 空间 | 模型权重增量空间 |
| 冻结 | 全部基座参数 | 全部基座参数及 A |
| 训练 | 一个任务一个 FP32 向量 v | General/Isolated 两分支的 B |
| 主位置 | 0-based layer 14 的整个 decoder block 输入 | 28 层 q_proj/k_proj/v_proj |
| 表示规模 | 2048 个可训练数 | 两分支 rank 各 8 |
| 复用 | 所有该任务输入复用同一个向量 | 所有该任务输入复用同一套适配器 |
| 迁移 | 目标 prompt 不变，替换源 v | 目标 prompt 不变，安装源实际更新 |

它们具有共同基座、数据和任务指令，但训练参数预算并不相等，不能把两路线的原始准确率差直接解释为表示空间的因果优劣。

**4.1 LTV：调整开始回答前的内部状态**

设第 14 层输入为 h，样本的 prompt 最后位置为 p。主实验仅执行 `h[p] + v_t`，其它位置不直接加向量。第 14 层按 0-based 编号，是第 15 个 decoder block。必须在整个 block 的 residual 输入处加，不能只给 RMSNorm 子模块输入加：Qwen3 在调用 norm 前已保存 skip residual，后一种写法会漏改跳连分支。[Qwen3 4.51.3 实现](https://github.com/huggingface/transformers/blob/v4.51.3/src/transformers/models/qwen3/modeling_qwen3.py)。

teacher forcing 时，输入虽然包含 prompt+完整答案，注入位置仍是原 prompt 末尾。第一回答 token 由该位置的 logits 预测，loss shift 和 mask 必须据此对齐。prompt 末尾是经过 chat template 序列化后的末 token，并非原始问题最后一个字；non-thinking 模板中固定的 assistant 前缀也属于这个边界的一部分。[tokenizer 配置](https://huggingface.co/Qwen/Qwen3-1.7B/blob/main/tokenizer_config.json)。

cache-on 生成只在 prefill 加一次，影响通过该层及后续层的缓存和状态传播。诊断用 cache-off 全前缀重算时，每一步都应在同一原 prompt 末位置重现这次干预，才是等价计算。不能凭缓存对象非空就断言已经进入 decode，因为空 DynamicCache 也可能预先存在。

全部基座参数冻结，但注入后的网络仍须对 v 反传。FP32 master vector 前向转成 hidden dtype 时保持可微；不能 detach。使用 non-reentrant checkpointing 时，反向重算仍要正确执行注入，hook 和位置元数据必须活到 backward 结束。“注入一次”不是禁止计算图重算。

层消融分别重新训练层 6、14、22；多层版本联合训练三个独立向量，不能把层 14 的向量直接移到别层充当层消融，也不能复制同一向量充当三个独立参数。

核验发现：官方主训练脚本和生成路径存在学习率、监督 token、hook 前后位置、采样配置等差异；多层生成还需要避免共享一次性状态造成漏注入。原文明确要求统一到自身协议，所以复用其思想与可核验逻辑，不直接照跑训练/生成脚本。[训练源码](https://github.com/HLYang2001/Learned_TV/blob/main/experiments/train_ltv.py)、[干预源码](https://github.com/HLYang2001/Learned_TV/blob/main/utils/hidden_states.py)。论文方法本身支持多 token 平均损失，“单 token 限制”针对该主要代码路径。

**4.2 LoDA-MT：从共同基座训练可比较的低秩更新**

原始 LoDA 是顺序持续学习，后一任务在已更新模型上继续学习。主实验为保证任务增量具有共同坐标起点，采用文档明确命名的 LoDA-MT 适配：每个任务 B 都从同一个冻结 theta0 训练。

每层每任务从训练集固定抽 128 条，在基座下收集真正的 QKV 线性投影输入，即该 block 首个 RMSNorm 之后的特征；每条至多均匀取 64 个非 padding prompt tokens。S_t 是未中心化的二阶矩，不能随手改成减均值的协方差。

General 取所有已见任务 S_t 之和的 top-8 特征子空间；任务 t 的 Isolated 使用 S_-t=其余已见任务统计之和，遵循 Cholesky 白化、特征分解、映回、QR 流程。正则项为 1e-4*trace(S_-t)/d。对子空间方向，核验得到：

\[
L_tL_t^T=S_{-t}+\epsilon_t I,\quad
H_t=L_t^{-1}S_tL_t^{-T},\quad
Z_t=\operatorname{TopEig}_8(H_t),\quad
Q_t=\operatorname{QR}(L_t^{-T}Z_t).
\]

A_I,t 的行空间为 Q_t^T，A_G 的行空间为 U_G^T。General 与 Isolated 各自正交化，不要求两者彼此正交；额外从 Isolated 剔除 General 方向会改变原方法。三角求解可以等价替代显式求逆；若统计退化或 Cholesky 失败，应记录并诊断，不能静默改变正则系数。

源码 A 使用 U^T/sqrt(3)，论文描述的基为 U^T；原文只固定子空间，未固定这个数值缩放，因此需要显式决定。统计使用token总和、token均值或样本内均值后再平均也不能混用；它决定长prompt的权重。上述细节须与固定源码版本对应。[分解实现](https://github.com/HHHLF/LoDA_ICML2026/blob/main/models/decomposed_lora.py)。LoDA B 的master参数/优化精度也尚未给定，不能因基座BF16就推定其优化状态精度。

各层 Q/K/V 共享输入子空间，但 B 输出尺寸不同：Q 为 2048，K/V 各 1024。须保留原生 GQA、Q/K normalization、RoPE、attention mask 和缓存行为；不能把 ViT 的等宽 QKV 拆分代码移植过来。

训练后保存 raw 与 recalibrated 两套分支。文档给定实际更新为：

\[
\Delta W_t=0.5 B_{G,t}\Lambda_t A_G+B_{I,t}A_{I,t}.
\]

未重标定版本等价于 Lambda=I。General 的 0.5 与 Isolated 的 1 不能改成两分支都乘 0.5，也不能另加普通 LoRA 库默认 alpha/r 缩放。后续 cosine、SVD、组合均针对应用这些系数后的实际增量。

按官方重标定源码映射，若 a_i 是 General A 的第 i 行，g_prev=a_i S_-t a_i^T，g_cur=a_i S_t a_i^T，则 eta_i=g_prev/(g_prev+3*g_cur+eps)，Lambda_ii=1-eta_i。eps 与 Cholesky 正则不是同一参数；含 eps 时不能擅自化成 3*g_cur/分母。究竟采用初始化时的固定基座统计，还是像顺序原法一样训练后重估，以及哪套更新作为主评测，都尚需锁定。

主实验的 B 独立训练，但 A 的结构来自全部已见任务。这属于允许的多任务结构先验，不能描述为每个任务完全不接触其它任务数据，也不能据 A_G 相同宣称自然共享能力。

顺序 LoDA 作为单独的语言模型适配对照，保留四种循环任务顺序并分开报告。其第一任务、后续统计更新和合并方式须单独核对，不能把主实验所有 A 冻结的流程直接改任务顺序就称为原始顺序 LoDA。普通独立 LoRA 如加入，只是可选 baseline。

**4.3 共用训练协议和 GAO 的特殊性**

| 设置 | LTV | LoDA-MT |
|---|---|---|
| AdamW lr | 0.001 | 0.001 |
| weight decay | 0.01 | 0 |
| 最多 epochs | 5 | 5 |
| batch | micro 2，累积 8，有效 16 | 逻辑 16，分成两个不相交的 8，micro 2 |
| 调度 | linear decay；warmup 0 | 同左；需明确两次更新的计数 |
| clipping | 1.0 | 外层 1.0；不能替换 GAO 内部归一化 |
| checkpoint | 调参集回答 NLL 最低，patience 2 | 同左 |
| 长度 | prompt≤512，target≤512，总≤1024 | 同左 |

统一损失是先在每个样本内部平均回答 token 的 CE，再平均样本。直接调用默认的整批 token 平均会让长答案权重更大，不符合原文。prompt/padding 不计损失；EOS、尾换行是否计入回答尚需写清。

GAO 的生成适配将原分类标签不相交改为样本不相交。一个逻辑 batch 的两组各 8 条，不是两个普通累积 batch。必须先积累完整源组的逐样本平均梯度，再按每个 B 参数张量单独归一化，不能逐 micro-batch 各自归一化。

官方实现每个逻辑 batch 抽一个负扰动系数 rho=-0.05*U(0,1)，先执行组1→组2的扰动、目标损失、AdamW更新和撤销扰动，再在已经更新的参数上执行组2→组1；两个方向复用 rho，不建立二阶梯度图。这意味着一个逻辑 batch 有两次 optimizer.step，不能把双向梯度先平均再只更新一次。[GAO 实现](https://github.com/HHHLF/LoDA_ICML2026/blob/main/methods/dlora.py#L246-L270)。文档指定按官方逐张量一阶范数流程，不能被一般 SAM 实现或论文中不同排版表达式替代。

在训练恰为 512 条、batch 16、跑满 5 epochs 的条件下，LTV 最多 160 次 optimizer step；GAO 为 160 个逻辑 batch、320 次 optimizer step。建议 linear scheduler 按实际 optimizer step 推进并显式记录两种计数；这是待锁定的调度实现口径，不是已完成的运行结果。

**5．E1–E6 的执行与统计计划**

**E1：先证明表示值得分析。** 每个任务比较基座、正确训练表示、随机同范数表示和未训练初始化。LTV 初始向量应原样保存；LoDA 的 B=0，因此未训练更新在数学上等价于基座，可在通过等价验收后复用基座预测，但必须在结果表明确该对照。随机方向的分布、重复数、全局还是逐层范数匹配，以及 LoDA 是否匹配权重矩阵秩，均需锁定。若无稳定正收益，先定位训练、注入、容量和任务适配问题，不能直接靠漂亮聚类图继续宣称共享。

**E2：区分几何结构和结构先验。** LTV 用同层、同坐标向量 cosine；多层版本和单层版本分开。LoDA 使用实际 DeltaW 的 cosine，以及明确左右子空间定义的分层 principal angles，不拼接 A/B。还要比较初始化/随机对照和跨 seed 结果。LoDA 单层更新本身因 rank8+8 而低秩，跨任务矩阵又至多秩 T，这些都不能作为新能力发现。

**E3：构建方向明确的矩阵。** 每条路线得到 4×4 矩阵，行是源任务表示，列是目标评测任务：

\[
M_{ij}=\mathrm{Perf}_j(\theta_0\oplus v_i)-\mathrm{Perf}_j(\theta_0).
\]

LoDA 中 v_i 对应源任务的实际参数增量。对角线是本任务有效性，非对角线是迁移。数学→逻辑和逻辑→数学是不同实验，矩阵不能强行对称化。

原始矩阵保留各列原单位；accuracy、chrF++、iBLEU 不直接相加平均。聚类前按目标任务基座逐样本分数的标准差做列缩放。sentence metric 与 corpus metric 的区别、标准差为零时的规则、层次聚类使用出向/入向/拼接画像及距离/linkage，均需预先锁定。建议发现集估计的列尺度在确认阶段保持冻结，避免确认集又参与结构定义。

指标实现也需冻结：chrF++应使用word n-gram order=2，而不能把默认chrF直接改名；固定完整signature。[SacreBLEU官方说明](https://github.com/mjpost/sacrebleu)。iBLEU通常定义为alpha*BLEU(生成,参考)-(1-alpha)*BLEU(生成,输入)，它奖励参考匹配并惩罚直接复制；alpha、分词、大小写、平滑与句级/语料级口径原文没有定值。[iBLEU原论文](https://aclanthology.org/P12-2008.pdf)。语义保持指标的模型/版本、复制率的文本规范化与判据也要单独规定。

paired bootstrap 对基座和干预使用相同抽样索引；BLEU/chrF++ 等 corpus 指标在每次重采样后重新聚合计算，不用句级平均冒充 corpus 分数。若同一 theory/连通组/程序下有多个样本，建议按独立分组单位重采样；同时单独报告 seed 间变化。随机数据重采样的区间不等于跨训练 seed 重现性。

任务组由发现集上的功能迁移优先决定，几何作为解释变量。保留单一组和无稳定组；不能预先固定两组。建议保存 bootstrap 共聚类频率并明确稳定性规则。四个任务只有六个无向任务对，跨空间相关性只适合作为小规模探索证据。

**E4：用操作证明成分的作用。** 先均值分解，再 SVD。V 的列为各任务的归一化向量，即形状 D×T；使用其左奇异子空间，但投影原始未归一化 v_t：s_t=U_q U_q^T v_t，r_t=v_t-s_t。q 只比较 0、1、2，发现集选定后锁到测试。

每个设置保留 shared-only、residual-only、shared+residual、删除 shared、随机同秩对照。在线性加法定义下，删除 shared 就是 residual-only，不应把二者当成独立的两份证据；shared+residual 必须恢复原表示和原行为。q=0 时 shared 为零，不允许做除零范数归一化。LoDA 人为的 General/Isolated 分支干预与这里对实际增量做出的 shared/residual 干预，应使用不同标签报告。跨任务向量矩阵的秩q与单个LoDA层权重矩阵的秩不同，“随机同秩”要注明匹配的是哪一种结构。

q和分组的选择须依据预先写定的发现集功能目标，不应单靠几何重建误差选择后就称为功能共享。候选数、跨任务分数如何比较、是否允许选择q=0和不分组，都应进入协议。

先做 global Shared/Specific；只有扩到六任务并发现稳定组后，才在去 global 残差上做组内 SVD。输出格式改变、逻辑标签重编码、prompt 改写是必需的混淆对照。每次对照都应给基座和干预完全相同的新模板，并用匹配评分规则；仅干预侧换模板不构成有效控制。具体采用固定已训向量的测试时变换，还是为变体重新训练，原文尚未说明，两者回答的问题不同；标签token长度变化也应记录。

**E5：检验组合收益，先定义组合任务。** 必需方法包括原表示、直接相加、平均、调权相加、分解后组合，以及范数匹配和相同调参预算：

\[
v_{compose}=\frac1{|S|}\sum_{t\in S}s_t+\sum_{t\in S}r_t.
\]

需要分别记录候选组合集合、每个方法候选个数/生成调用预算、强度/权重搜索空间、选择集和每任务评分，不能让分解方法比平均 baseline 多调参。

两个代数边界必须核验：q=0 时分解组合退化为直接求和；q 覆盖全部输入表示时退化为平均。如果均值 s 在同一组任务上定义，并对整组组合，结果也恰是普通平均。发生这种等价时，代码应标记等价，不能宣称算法收益。

目前原文没有规定组合任务具体输入、答案和指标。把混合向量在原四任务上分别评测，只能直接支持多任务能力保留/折衷；真正的串联或组合能力需要另外锁定相应数据和评分协议。此处不能由代码自行发明一个 benchmark 再称为文档要求。

TIES、TSV、KnOTS 保留在后续 baseline 工作清单，按原仓库定义核验其适用范围和语言模型接入；不能自动套到 LTV 后仍称原论文算法。[TIES](https://github.com/prateeky2806/ties-merging)、[TSV](https://github.com/AntoAndGar/task_singular_vectors)、[KnOTS](https://github.com/gstoica27/KnOTS)。尤其 TSV 的层内矩阵 SVD 不等于本方案跨任务向量矩阵 SVD。各 baseline 的精确变体和预算在 E5 前锁定；普通独立 LoRA 属于可选补充。

**E6：真正不接触留出任务。** 原文要求完全留出一个任务后重建结构，留出哪些任务尚需锁定。建议进一步对四个任务轮流留一；若采用四折，每折重新选结构、秩与系数，全部只基于其余三个任务允许使用的数据。不能训练留出任务向量后投影它，再把这一结果叫作不使用新任务数据的零样本迁移。应用给新任务的 shared/组合表示，应完全由已见任务构造和选定。

LTV 各任务独立，可以复用其余任务已有训练向量，再在允许的发现数据上重建结构。LoDA-MT 的 A 原本用到全体任务 S，必须从统计构建处排除留出任务，重建剩余任务的 A_G/A_I，再从 theta0 重训剩余 B；仅从四任务旧向量矩阵删掉一列仍有泄漏。若采用建议的四折，则另有 4×3=12 个 LoDA-MT 训练实例/seed；单一留出则为3个，不能把四折预算误称原文固定要求。

SAMSum 是额外新任务，只做未参与构建/选系数的确认；摘要 prompt、指标、split、长度和样本数尚未给出，需补协议。凡用目标任务数据调整表示强度、秩或系数的设置，应单列成额外的目标适配实验，不能替代原文 E6。

两路线的一致性比较使用相同任务顺序下的几何关系矩阵、迁移方向、分组稳定性和任务对排序；不计算 2048 维 LTV 与数亿维 DeltaW 的直接 cosine。不同路线若出现不同结构，也是有解释价值的结果。

**6．预算核算与阶段测试集使用**

文档的 9216=（1 个基座+4 个 LTV+4 个 LoDA-MT）×4 个目标任务×256 条，算术正确，但只覆盖核心九个状态，不能完整代表 E1+E3 的所有生成。

| 工作 | 生成次数/seed | 范围说明 |
|---|---:|---|
| 九状态最终测试核心面板 | 9216 | 原文明确的口径 |
| 同九状态的发现集面板 | 4608 | 9×4×128；若两路线各做矩阵，基座可共享 |
| E1 随机同范数，最少每个任务/路线一个，仅测对应任务 | 2048 | 8×256；随机重复数增加则按比例增加 |
| E1 LTV 未训练初始化，仅测对应任务 | 1024 | 4×256；LoDA 零更新可复用基座预测 |

若把所有 E1 额外状态也迁移到所有目标任务，若比较 raw/post LoDA，或增加随机重复、模板控制、层消融，则预算继续增加。NLL 验证不等于生成；调参集强度搜索、E4–E6、顺序 LoDA、代码任务均未包括在上表。

256 条准确率测试对小收益较不敏感，不能只看单个点估计。三训练 seed 的核心九状态面板如完全重复为 27648 次生成；同配置同硬件下基座可在验证行为一致后复用，实际唯一生成量应以 manifest 为准。

原文同时规定“最终测试只在方案锁定后使用”和“先用256完成E1/E3验收”。建议采用显式阶段锁定：调参/发现完成→冻结 E1/E3→解封256确认。若看到这些结果后改变后续方法或选择假设，应使用预先另留的确认样本或正式扩大后的独立部分，不能继续把已见256称为全新的未见证据。也可在首次解封前锁定全套后续分析。此处需要在运行协议中明确，不能靠执行顺序隐含解决。

**7．资源理解：小参数量不等于零训练成本**

按文档规划单张 24GB NVIDIA GPU、micro-batch 2，必要时 non-reentrant gradient checkpointing。该容量尚未实测，也没有时间估算依据；BF16 能力、CUDA/PyTorch版本和真实峰值需后续 preflight 检查，不自动切换量化或更小模型。

从官方形状推导：两分支 rank 各 8、共享 A、Q/K/V 分别输出时，每任务可训练 B 数约为 28×16×(2048+1024+1024)=1,835,008。LTV 主设置为 2048 个参数，多层为 6144。两者不属于参数量匹配实验。

每任务全部 QKV 的稠密增量含 28×(2048×2048+2×1024×2048)=234,881,024 个元素；FP32 约 896MiB，四任务约 3.5GiB。这个数字只计算增量，不含模型、激活、优化器、统计和分解工作区。

建议训练保存低秩因子和精确缩放，分析时按层流式计算实际增量内积，必要时借小 T×T Gram 矩阵得到与全局 SVD 等价的结果；不能以省显存为由改成对因子拼接做 SVD。组合后的矩阵秩可能超过单任务 rank16，禁止静默截断回16。二阶矩/特征分解按层处理，记录精度和正则/回退信息。

**9．关键验收用例与必须保存的证据**

验收重点是能发现科学协议偏差的检查，不追求机械增加测试数量：

- loss：长短回答人工例，验证每样本等权、prompt/pad不计、首个回答token shift正确；不同micro拆分与逻辑batch梯度一致。

- LoDA：B=0恢复基座；A/基座权重不变；真实QKV形状；SVD/Cholesky/QR数值残差；raw/post公式；低秩与稠密更新行为一致。
- GAO：参考小例逐步核对扰动方向、逐张量norm、组间无重复、两次AdamW更新、撤销扰动、无二阶梯度；micro2模拟组8结果正确；scheduler步数与日志一致。
- 分解/组合：s+r=v；q0边界；均值退化边界；实际DeltaW内积与稠密小例一致；随机同秩/同范数；组合不偷偷压回单任务秩。

总体实施原则是：文档定死的设定严格执行；明确的语言模型适配如实命名；尚未定死的细节显式记录并锁定；未通过的环节如实报告；延后的实验保留在需求矩阵，不能以工程方便为由消失。
