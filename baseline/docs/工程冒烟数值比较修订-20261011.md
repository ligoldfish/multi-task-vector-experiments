# 工程冒烟数值比较修订（2026-10-11）

本修订只调整真实模型的工程冒烟判定，不调整原实验的模型、数据、BF16 精度、注意力实现、训练超参数、向量注入位置、生成方式和正式实验范围。

## 触发证据

ModelMate 的 Ascend 910B3 / PyTorch 2.8.0 / torch_npu 2.8.0.post5 / Transformers 4.51.3 上，首次 math 冒烟已完成 LTV 更新及保存重载，但完整教师序列与单条短提示序列的末提示 logits 未通过原容差 `atol=0.03125, rtol=0.015625`。

保留的前向诊断使用相同两条训练样本及失败尝试保存的工程 LTV。BASE 与 SAVED_LTV 的同形状重复、未来答案替换、显式 mask 与省略 mask、完整输出与末 token 输出均精确一致。跨 batch/序列长度的差异在第 1～2 层即出现，早于第 14 层 LTV 注入；原 teacher/prefill 对照最大差异为 BASE 0.5390625/0.875、SAVED_LTV 0.875/0.5625，四个实际 argmax 均相同。`topk` 对并列分数的返回顺序不能代表 argmax 已翻转。

诊断日志：`environment/prefill-diagnostic-20261011T150017Z.log`。诊断 JSON：`environment/prefill-diagnostic-20261011T150120.309543Z-207905/diagnostic.json`。原失败日志和 `runs/smoke.json`、`runs/smoke_ltv.pt` 均保留。

## 修订后的判定

- 同一计算形状下，对 BASE 和 LTV 分别严格检查：替换未来答案不能改变末提示 logits；将每条 prompt 之后的 mask 置零形成仅提示可见上下文，也不能改变末提示 logits。两项使用零容差。
- BF16 跨形状 teacher/prefill 比较仍报告原容差、最大差异和是否落在原容差内；将该全词表数值比较明确标为诊断项，不提高容差，也不声称原 allclose 已通过。
- 原实际首 token argmax 一致、缓存与完整前缀三 token 生成一致的硬检查保留。增加同形状缓存开启与关闭的 prefill 一致检查。
- 非 BF16 跨形状 allclose 检查继续作为硬检查。
- 原冻结基座、保存重载、干预上下文退出恢复、LoDA 零更新、raw/post 导出、真实 GAO 更新与断点恢复检查均保留。

新的 `passed=true` 表示上述明确修订的工程合同及原其余检查通过，不表示跨形状 BF16 全词表数值等价，也不表示科学实验成功。
