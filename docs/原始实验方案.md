# Multi-Task Vector Discovery and Decomposition：研究目标与实验方案

我们的研究目标是：**用固定的 LTV 和 LoDA 两条路线构建任务表示，检验不同任务是否共享可迁移的功能成分，并判断这些成分能否改善任务组合和未见任务表现。**

重点不是提出新的 Task Vector 抽取算法，而是回答：

> **几何上相似、可以低秩分解的任务向量，是否真的包含具有跨任务作用的共享能力？**

LTV 已研究过任务相似性、迁移和组合；LoDA 已包含 General / Isolated 分解。因此，新增贡献应集中在**排除格式与标签混淆后的功能共享、留出任务验证，以及两种表示空间中任务关系的一致性**。

以下是建议的可执行 MVP 设置；**这些是拟采用的超参数，尚未训练验证。当前项目目录为空，没有可直接复用的本地代码。**

**1．模型、任务与数据**

统一使用 `Qwen/Qwen3-1.7B`，BF16，`enable_thinking=False`。该模型有 28 层、hidden size 2048。[模型配置](https://huggingface.co/Qwen/Qwen3-1.7B/blob/main/config.json)

先做四个任务，之后加入两个代码任务：

| 阶段 | 任务 | 数据来源与构造 | 主要评价指标 |
|---|---|---|---|
| MVP | Math Reasoning | GSM8K；训练使用解题过程和答案 | 完整生成后的最终答案准确率 |
| MVP | Logical Deduction | ProofWriter，推理深度 0–3 | True / False / Unknown 准确率 |
| MVP | Translation | IWSLT2017，英语→德语 | chrF++，补充 BLEU |
| MVP | Paraphrasing | QQP 正例，问题一→等义问题二 | iBLEU，补充语义保持与复制率 |
| 扩展 | Code Generation | MBPP | 单次生成通过全部测试的比例 |
| 扩展 | Code Repair | 对 MBPP 正确程序施加可验证的错误 | 修复后通过全部测试的比例 |

四任务覆盖“数学与逻辑推理”和“保持语义的文本转换”，但**不预设它们一定形成这两个组**。QQP 用于生成属于我们的数据适配，需排除近乎直接复制的收益。

每个 MVP 任务固定：

- **训练 512 条**。
- **调参集 128 条**：选 checkpoint、干预强度。
- **结构发现集 128 条**：构建迁移矩阵、选择分解秩和任务组。
- **最终测试 256 条**：只在方案锁定后使用；正式实验扩到 1000 条或完整测试集。
- 先跑 seed `17`；通过有效性检查后增加 `29、43`。

训练、调参和结构发现数据从官方训练划分中选取；最终评测使用独立、有标签的官方评测划分。ProofWriter 按 theory 分组，QQP 按重复问题连通组分组；Code Generation / Repair 必须按原始程序 ID 联合划分。

MBPP 的官方完整配置训练集只有 374 条，扩展阶段建议两个代码任务各用 **300 条训练数据**，不要为了凑到 512 条混入测试题。[MBPP 数据说明](https://huggingface.co/datasets/google-research-datasets/mbpp/blob/main/README.md)

**2．两条 Task Vector 路线**

| 设置 | LTV：Activation Space | LoDA：Parameter Space |
|---|---|---|
| 优化对象 | 可训练向量 \(v_t\) | 两分支上投影 \(B_{G,t},B_{I,t}\) |
| 冻结部分 | 全部 LLM 参数 | 全部 LLM 参数及下投影 \(A_G,A_{I,t}\) |
| 位置 | 第 **14 层输入 residual stream**，0-based，在该层 RMSNorm 前 | 28 层 attention 的 `q_proj/k_proj/v_proj` |
| 主设置 | 单层、单位置，2048 维 | General rank 8 + Isolated rank 8 |
| 初始化 | 独立采样 \(U(-0.1,0.1)\)，向量用 FP32 优化 | 数据统计构建 \(A\)，\(B=0\) |
| 任务损失 | 仅目标回答 token 的平均交叉熵 | 相同的回答 token 交叉熵 |
| Optimizer | AdamW | AdamW，配合 GAO |
| Learning rate | **0.001** | **0.001** |
| Weight decay | 0.01 | 0 |
| 训练轮数 | 最多 5 epochs | 最多 5 epochs |
| Batch | micro-batch 2，累积 8，effective batch 16 | 一个逻辑 batch 16，分成两组各 8；micro-batch 2 |
| 其他 | linear decay，warmup 0，grad clip 1.0 | linear decay，warmup 0，外层 grad clip 1.0 |
| Checkpoint | 调参集回答 NLL 最低，patience 2 | 同左 |
| 训练长度 | prompt ≤512，target ≤512，总长 ≤1024；不截断答案后继续训练 | 同左 |

训练损失统一为每个样本先对回答 token 求平均，再对样本求平均：

\[
\mathcal L_t=
-\frac1{|\mathcal B|}
\sum_{(x,y)\in\mathcal B}
\frac1{|y|}
\sum_{k=1}^{|y|}
\log p(y_k\mid x,y_{<k};v_t).
\]

推理全部使用相同任务指令，MVP 用确定性 greedy decoding。生成上限：数学 512、逻辑 32、翻译 256、改写 128 tokens；代码扩展为 512。记录截断率。

**LTV 的实现边界**

- 主实验只在 **prompt 最后一个 token** 注入一次；teacher forcing 时也是这个固定位置，不是答案末尾。
- 自回归生成时只在 prefill 注入，通过后续层的 KV cache 传播影响。
- 向量可跨输入复用；换任务时保持目标任务的输入和指令不变，只替换注入向量。
- 层消融分别训练第 `6、14、22` 层；多层版本再联合训练 `[6,14,22]` 的三个独立向量。

官方代码存在需要处理的差异：论文写学习率 0.001，训练脚本用 0.005；主要训练函数只监督一个标签 token；训练代码在 block 前注入，生成函数却使用 block 后 hook。我们的实现应明确统一为上述位置，并扩展为完整回答损失，不能直接照搬生成脚本。[训练代码](https://github.com/HLYang2001/Learned_TV/blob/main/experiments/train_ltv.py)、[注入与损失代码](https://github.com/HLYang2001/Learned_TV/blob/main/utils/hidden_states.py)

**LoDA 的实现边界：明确称为 LoDA-MT 适配**

原始 LoDA 是顺序学习：在前一任务更新后的模型上继续训练，最后重标定、合并更新。因此，原始顺序增量不能直接当作从同一个基座独立获得的任务向量。

主实验建议采用以下适配：

1. 所有任务从同一个冻结基座 \(\theta_0\) 出发。
2. 每任务取训练集中的 128 条，收集各层 QKV 输入特征，估计二阶矩 \(S_t\)；每条最多均匀取 64 个非 padding prompt tokens。
3. 保留 LoDA 的 General 能量目标：
   \[
   U_G=\operatorname{TopEig}_8\left(\sum_t S_t\right).
   \]
4. 为任务 \(t\) 构造 Isolated 子空间：将原方法的“过去任务统计”换成
   \[
   S_{-t}=\sum_{j\ne t}S_j,
   \]
   再使用官方的 **Cholesky 白化→特征分解→QR** 流程。
5. 冻结两个 \(A\)，只训练两个 \(B\)，保留 GAO；生成任务将“标签不相交分组”改为“样本不相交分组”。**这是明确的适配，不等同于原论文的分类设置。**
6. 保存重标定前、后的两套分支更新：
   \[
   \Delta W_t=0.5B_{G,t}\Lambda_tA_G+B_{I,t}A_{I,t}.
   \]

具体设置：`rho_max=0.05`、重标定 `lambda=3`；二阶矩正则项取 \(10^{-4}\operatorname{tr}(S_{-t})/d\)。GAO 采用官方代码的逐参数张量梯度归一化、双向更新，不计算二阶梯度。

Qwen3 的 Q/K/V 输出维度不同，应共享输入子空间、分别输出对应尺寸，保留原模型的 GQA、Q/K normalization 和 RoPE。[LoDA 分解代码](https://github.com/HHHLF/LoDA_ICML2026/blob/main/models/decomposed_lora.py)、[GAO 代码](https://github.com/HHHLF/LoDA_ICML2026/blob/main/methods/dlora.py)

另设小规模 **顺序 LoDA 对照**，用四种循环任务顺序检查顺序影响；它与 LoDA-MT 分开报告。普通独立 LoRA 如加入，只能叫 baseline。

**3．实验顺序与要检验的问题**

| 实验 | 具体操作 | 通过什么证据支持结论 |
|---|---|---|
| E1 向量有效性 | 基座、正确任务向量、随机同范数向量、未训练初始化向量 | 正确向量稳定改善对应任务 |
| E2 几何关系 | LTV cosine；LoDA 实际 \(\Delta W\) 的 cosine、分层子空间夹角 | 关系跨 seed 稳定，且不由初始化决定 |
| E3 跨任务迁移 | 每个源任务向量干预全部目标任务 | 得到有方向的功能迁移关系 |
| E4 成分干预 | 分别施加 shared、residual、两者合并及删除 shared | shared 的跨任务作用超过随机同秩对照 |
| E5 组合 | 原向量、直接相加、平均、调权相加、分解后组合 | 在相同调参预算、范数条件下改善组合 |
| E6 未见任务 | 完全留出一个任务重建结构；补充 SAMSum 摘要 | 不使用新任务数据选择分解或系数仍有收益 |

迁移矩阵严格定义为：

\[
M_{ij}=\mathrm{Perf}_j(\theta_0\oplus v_i)
-\mathrm{Perf}_j(\theta_0).
\]

**不要直接平均准确率、BLEU 和改写指标。**保留原始指标矩阵；用于聚类时，再按目标任务的基座逐样本分数标准差进行列尺度标准化，报告 paired bootstrap 置信区间。

任务发现优先采用**结构发现集上的功能迁移关系 + 简单层次聚类**；几何相似性作为解释变量。保留单一组、无稳定分组的结果，不强迫四任务形成两组。最终测试集用于确认发现集上的关系，避免循环论证。

**4．共享与特有分解：先用最简单版本**

先做均值基线：

\[
s=\frac1T\sum_t v_t,\qquad r_t=v_t-s.
\]

再做低秩投影。将同一路线、同一坐标定义下的归一化向量组成矩阵 \(V\)，做 SVD：

\[
V=U\Sigma R^\top,\qquad
s_t=U_qU_q^\top v_t,\qquad r_t=v_t-s_t.
\]

- 初始只比较 \(q\in\{0,1,2\}\)，其中 \(q=0\) 表示不使用共享成分。
- 用结构发现集选择，测试集锁定。
- LoDA 对 **\(BA\) 对应的实际更新**分解，不直接拼接 A/B，避免因子参数化歧义。
- 先做 Shared / Specific；六任务出现稳定分组后，再对去除 global 后的残差做组内 SVD。

最重要的两个限制：

1. **四个任务的矩阵天然至多秩四，不能把“低秩”本身当作发现。**
2. **LoDA-MT 的 \(U_G\) 是人为共享的，不能用它相同来证明自然共享能力。**必须检查训练后的实际更新和分支功能。

组合可以测试：

\[
v_{\mathrm{compose}}
=\frac1{|S|}\sum_{t\in S}s_t+\sum_{t\in S}r_t.
\]

但必须包含平均向量、调权相加和范数匹配对照；在一些情形下，“共享去重”会退化为普通平均，不能据此宣称新算法。

还要加入**输出格式改变、逻辑标签重编码、prompt 改写**对照：如果共享效果随这些表面变化消失，更合理的解释是格式或标签共享，而非推理能力共享。

**6．第一阶段执行范围**

按**单张 24GB NVIDIA GPU**规划，micro-batch 2，必要时启用非重入 gradient checkpointing；这是容量估计，实际峰值要在实现后测量。LTV 参数很少，但长回答损失仍需要后续网络反向传播。

第一轮只做 **4 个 LTV + 4 个 LoDA-MT + 基座**，完成 E1 和 E3。所有状态评测四任务各 256 条，共 **9216 次生成**，不含调参集。

验收重点是：保存重载保持行为一致、训练与推理注入一致、任务向量确实有效，以及迁移关系能跨 seed 重现。**这些成立后，再投入共享分解、组合和未见任务实验。**
