# 加速版验证报告

本地验证环境：Windows、Python 3.10.13、PyTorch 2.8.0 CPU、Transformers 4.51.3、SacreBLEU 2.5.1。此处没有 Ascend NPU，不能据此宣称 CANN 实测兼容或全程加速比。

完整回归为 **350 passed、1 skipped，286.88 秒**；后续监控与顺序对照接线补验为 **12 passed，24.28 秒**。两份报告按测试名称去重后，共 **354 个通过、1 个跳过、0 个失败**。唯一跳过项是要求真实 NPU 的 AdamW portable checkpoint/resume 测试；交付指南要求在 ModelMate 执行完整真实模型 smoke，覆盖实际 GAO、导出、断点重载与不重复更新。

完整机器记录见 [全量 XML](validation/validation-accelerated-full.xml)、[补验 XML](validation/validation-accelerated-supplement.xml) 和 [去重统计与未修改文件哈希](validation/acceleration-evidence.json)。

重点验证内容：

- 生成循环与原始循环的输入、输出、KV cache、EOS、左 padding 和干预清理等价；有限 logits 检查不增加每步主机回传。
- validated 模式可选择 token 或合法 EOS/长度结果不同的有效 batch；差异如实记录。strict/audited 保留各自一致性要求。
- 只读源任务 train/tune 校准，禁止 test/discovery 选择；固定任务/提示变体的策略持久化，并校验冻结契约。
- 分片覆盖每个 ID 恰好一次、恢复原样本顺序、worker 异常不提交不完整面板，退出时 terminate/kill 并回收。
- 后续训练与层消融使用阶段内独立任务池；12 个独立 seed/order 可并行，但每个顺序四阶段仍依次执行。
- 顺序对照明确使用 CPU 协调模型恢复/校验，在 NPU 池读取真实已合并的原生 dtype 权重生成；不额外占用第九份 NPU 模型。
- bootstrap 保留原组依赖、随机采样、求和顺序、2000 次结果分布和最终 CI；语料级指标与官方未缓存路径精确相同。
- 保留严格首轮、门禁、留出、扩展、控制组、正式扩评等原工作流回归；加速工程配置单独冻结，不绕过源码或数据一致性检查。
- 新目录准备拒绝覆盖，逐划分验证字节与数量；只复制相同数据，不复制旧训练/预测、不重写旧锁。
- 八卡启动探测只使用 train，三 token 的临时预算不修改正式配置，也不将 math 的正式推理策略冻结成 strict。
- 监控只读 JSON，不加载 `.pt`、不以 Notebook 硬件活动推断训练容器状态。

源码覆盖检查确认原目录中的源文件均保留。下列 15 个核心实现与原版本逐字节一致：data、prompts、training、ltv、loda、gao、subspaces、representations、losses、baselines、joint、sequential、modeling、code_execution、io。原始实验方案和补充协议亦逐字节一致。发生变化的生成、评分缓存、配置/流程接线均有回归验证；这不等于承诺大 batch 下每条 BF16 预测与旧版相同。

部署文档中的全部 Bash 命令通过 `bash -n`，嵌入 Python 通过 AST 解析。文件保存在 `validation/deploy-*.sh`，可与指南对照。

局部 CPU benchmark（64 条合成样本、50 次重采样，原/加速结果完全相同）：翻译 22.238 秒 → 0.975 秒；改写 11.205 秒 → 0.768 秒。它只说明统计模块的重复计算减少，不能外推为 NPU 或完整研究的加速倍数。

远端仍需验证：新源码的完整真实模型 smoke、独立训练容器八卡启动探测、实际选定 batch、各卡吞吐/显存、首批正式面板耗时。发生科学门禁失败时仍保存证据并停止依赖阶段，不为完成范围放宽门禁。
