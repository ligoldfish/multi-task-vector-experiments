# 工程检查点兼容修订（2026-10-12）

## 已观察到的问题

真实 Ascend 910B3、PyTorch 2.8.0 / torch_npu 2.8.0.post5 工程冒烟已完成一轮 LoDA GAO：16 个训练样本组成一个逻辑批次，两个不相交的 8 样本组执行双向更新，优化器与调度器各更新两次。随后读取 `last.pt` 失败。

对该检查点作不执行 pickle 的静态检查，确认 AdamW 的 `exp_avg` 包含 NPU 重建函数以及通过 `getattr(Format, "ND")` 重建的设备格式。`map_location="cpu"` 本身不能消除这些序列化引用；原来的 `weights_only=True` 加载器拒绝其中的 `getattr`。

## 永久修复范围

只修改 `atomic_torch_save`：保存前递归建立 CPU 张量副本，保留原 dtype、shape、数值、整数键、列表/元组结构和 OrderedDict 元数据。实际训练中的适配器、AdamW 状态和 RNG 状态不被修改；保存继续使用原子替换。

读取仍使用 `weights_only=True`。本修订不增加全局 allowlist，也不加载旧 NPU 优化器 pickle。训练公式、GAO 顺序、超参数、样本划分、模型、精度、子空间算法、raw/post 定义与原有冒烟检查均不改变。

## 本次恢复方式

旧 attempt 的所有产物保留。恢复工具从其 `initial.pt` 读取已经求出的 A_G、A_I、Lambda 与元数据，从两份 CPU 统计文件恢复 S_self、S_other。只有完整子空间内容摘要与原训练 provenance 完全一致、原配置/模型/数据/样本及编码符合要求时才复用这些工程校准资产。

在新的 attempt 中执行修复后源码的完整 `run_smoke`。仅在该调用期间将两次工程统计采集和一次工程子空间构建替换为已验证的相同内容；不重新做耗时的特征分解。正式实验入口和子空间构建函数的持久实现保持原样。

完整冒烟会重新执行一次 16 样本工程 GAO 逻辑批次，验证新检查点可以被普通 weights-only 加载、实际续接恢复全部状态且不重复优化步，继续验证 raw/post 导出、真实模型 logits、RNG 和上下文退出。新检查点来源绑定当前源码，不改写旧检查点的来源信息。原记录中的该批次训练用时约 46 秒；这不是新 attempt 的总耗时承诺。

新 attempt 全部检查通过且被原 workflow 接受后，才更新 canonical `smoke.json`；更新前保留其原始字节备份。任一失败都保留新旧证据，不发布通过状态。

## 验证与状态边界

`tests/test_portable_checkpoint.py` 验证嵌套状态的精确保存/读取、独立副本、保存失败保留旧文件，以及可选真实 NPU AdamW 保存/续接。`tests/test_portable_recovery.py` 验证工程缓存与发布约束。

Windows 本地没有 torch，故本地只执行适用的标准库测试、语法检查和补丁安装验证。张量及 NPU 测试应在现有 Notebook 环境运行，远端实际输出决定是否通过。本补丁和恢复工具不提交正式训练作业，也不产生正式科学训练或评估结果。
