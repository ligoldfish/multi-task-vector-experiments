# 补充协议与实现选择

本文件区分用户批准内容、原文未定的显式实现选择和实际运行证据。实现这些选择不表示实验证实了共享能力。

## 已获用户批准

1. 平台改为 ModelMate Ascend 910B 八卡；CANN8.5.0-a3，PyTorch/torch_npu2.8.0。模型、数据和持久化资产均位于 `/opt/dpcvol/datasets/`；精确子路径通过配置指定。用户报告显存“八卡共64G”，实际容量以 `preflight.json` 为准。
2. E5 包含原任务能力保留面板及双任务联合输入；分别评分并报告联合成功/达标。
3. MBPP 官方 train 按程序 ID 联合划分300/37/37，独立官方 test256；四个 MVP 任务轮流留出，另测 SAMSum。
4. LoDA 校准统计为所有所选 prompt token 的未中心化二阶矩均值；A 等于子空间基转置除 sqrt3，B 用 FP32 master 优化。
5. MT 重标定固定使用 theta0 校准统计、lambda3；raw/post 均保存，post 为主。逐 epoch 以回答 NLL 选择 checkpoint；迁移主强度1，同预算调参结果另列。

## 公开记录的实现选择

- 完整监督包含 EOS；Qwen nonthinking assistant prefix（含模板已有空 thinking scaffold）属于 prompt，不属于训练答案。所有路线使用相同编码。
- iBLEU alpha=.9，corpus BLEU 用 SacreBLEU13a/exp；句级分数仅用于标准差或联合阈值，不冒充 corpus BLEU。语义保持采用离线 all-MiniLM-L6-v2 的源问题/参考与预测 cosine；复制率为 NFKC、大小写和空白规范化后的完全复制，同时附词重叠率。
- 翻译 chrF++ 用 char6/word2/beta2；摘要用 stemmed ROUGE1/2/L F1×100。每次输出 scorer signature/version。
- 连续指标联合成功没有天然真值。默认在 **tune** 的 BASE 句级主指标中位数设置冻结阈值，标签为“联合达标率”；数学/逻辑采用准确、代码采用全部测试通过。阈值与样本 ID 写入 lock，联合评分绝不现场拟合。用户可在正式锁定前指定其它可审计判据。
- 发现秩的选择目标为源任务主指标增益除各源 BASE 句级标准差后的平均，原单位增益同时完整保存。零标准差列保留原单位结果，在标准化目标/聚类中排除。q=0 或简单候选在并列时优先。
- 聚类采用 outgoing 功能迁移 profile、average linkage，group bootstrap coassignment 稳定性阈值配置显式记录；允许单组与无稳定组。六任务跨 seed 稳定分组才进行去 global 后的组内 SVD。
- E5 每种策略使用相同候选评测预算；调参目标仅用被组合的源任务 tune 面板。原始范数和相对于 pair mean 的范数匹配分别报告。零强度保留为 BASE；同范数使正强度候选重合及 sum/mean 重合时，记录其退化，不称其为不同有效超参数。
- 联合输入/输出各采用1536 token上限，以容纳两个完整512 token子任务及联合指令、JSON键和转义开销；这是原文未指定的联合协议补充，单任务512 prompt/各任务生成上限完全保留。保存完整联合参考长度及超过预算标记，不修改或截断答案来规避预算。
- 完整尾批保留所有样本；LoDA 尾批近等分为两组。如余1条，从前批移动1条，记录真实分组和 optimizer step。绝不复制样本凑8/8，绝不丢弃尾批。
- 顺序 LoDA 采用官方 firststage 训练 A_G+B_G、关闭 isolated，随后冻结 A；过去统计按官方训练后和 merge 后两次积累，重标定用顺序当前统计。它与固定 theta0 的 MT 实验分开报告，保存 BF16 merge 舍入后的真实累计更新。
- TIES/TSV/KnOTS 属于参数组合 baseline，严格保存实际合并更新及增加后的秩；源码参考与 QKV 适配见官方合并基线说明。
- 有效性与重现门控是预先声明的执行规则：保存重载/注入一致；对应任务正确表示超过 BASE 和初始化/随机对照；有向功能迁移跨 seed 重现。门控阈值及结果保存在配置和 gate 文件。失败与负结果保留，不自动改科学设置继续。
- 跨 seed 功能重现默认要求全部有向 off-diagonal 迁移的符号一致率至少 .8、标准化增益 Spearman 至少 .5；常数 profile 无法定义相关时要求符号全部一致，零容差1e-12。这些是文档未给数值的公开工程门控默认值，不是作者论文的原始阈值，也不代表统计显著性。两表示空间之间的一致或不一致均报告，不要求人为一致。
- NPU 一卡一独立任务；并行提高吞吐，不改变有效 batch16。`eager` 注意力与非重入 checkpoint 避免依赖 CUDA 专用内核。真实峰值/吞吐由线上验证给出，不从 CPU toy 结果外推。

## 容量冲突与证据边界

2026-10-10 一致性修复只改变流程和证据完整性，不改变上述科学设置：严格首轮使用独立 core lock 并记录9216条核心预测；`full` 自动完成256主评测后接全部正式扩评，`formal` 只评测已完成训练；层与顺序对照纳入两层评测。已锁定候选不重选、不重导出；按模型/源码/数据/实际表示及逐样本内容核对后复用重叠预测，完整 corpus 指标重新计算。共享与同秩随机成分补直接配对差值区间；发现关系在锁定测试中确认。联合 bootstrap 按共享任一原始子任务组的传递连通分量抽样，只有一个独立簇时明确声明区间不可识别。

源码、训练表示、候选及恢复状态具有来源和内容摘要；旧版缺少这些信息的产物不能自动认定兼容。新代码使用新运行目录，不覆盖旧证据；若已有旧版在运行，应保留原包完成或先审查迁移。冻结协议后修改源码、数据或方法属于新的运行，不能继续沿用已解封测试的独立确认名义。

MBPP 374条官方 train 恰好对应300/37/37；原程序验证、可验证 mutation 和联合长度过滤可能降低容量。默认完整记录拒绝 ID 并停止，不混入评测题、不省略验证、不截断答案。用户决定缩减样本或更改长度后，应写补充协议、准备新清单并使用新运行根目录。

本机没有 NPU、正式数据和指定模型资产，CPU 测试只能验证数学及程序语义；所有正式数据容量、实际 NPU 兼容与 E1–E6 科学结果均待 ModelMate 执行。远程运行不能通过本地源码测试自动视为已完成。
