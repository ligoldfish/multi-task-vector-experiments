# Task Vector ModelMate 只读监控

将 monitor_task_vector.py 上传到 /home/work/user-job-dir/app。不要放进原项目的 src、ops、deploy 等目录，不需要修改已提交作业或重新提交。

脚本只使用 Python 标准库，读实验 DPC 中的 JSON、有限日志尾部和文件属性；不加载模型、不读取 .pt 内容、不获取 Notebook 的进程/NPU来推断训练容器，不写 ledger/checkpoint/smoke/实验源码，不发送停止信号。

## 先取一次快照

```bash
bash <<'BASH'
set -euo pipefail
python -u -B /home/work/user-job-dir/app/monitor_task_vector.py --count 1
BASH
```

默认自动选择最新 full worker（包括其 full-formal 兼容名），选择后本次监控固定该 worker，不跳到其他重试。输出 WORKER_EVIDENCE 应与本次网页运行日志 TASK_VECTOR_PLATFORM_JOB_DIR 指向的目录一致。它是内部 full-<时间-PID>，不是网页 data-... 作业 ID。

若要明确指定目标，使用从本次运行日志复制的内部目录或 ID：

```bash
python -u -B /home/work/user-job-dir/app/monitor_task_vector.py --job 'full-这里替换为本次内部ID' --count 1
```

入口失败还没创建 worker 时没有可监控的 DPC worker。旧 worker 的终态不能代表刚提交的新批次。网页状态始终独立核对，脚本明确标为 UNKNOWN。

## 每分钟刷新

```bash
bash <<'BASH'
set -euo pipefail
python -u -B /home/work/user-job-dir/app/monitor_task_vector.py --interval 60 --count 0
BASH
```

Ctrl-C 只停止这个监控器；训练不受影响。worker 记录终态后监控自动退出。终态 completed、failed、interrupted、stopped_by_gate、report_failed 会分别报告；科学门禁停止不等于基础设施错误。

需要保存本次监控输出时，可在上述 python 命令末尾加：

```bash
2>&1 | tee "/tmp/task-vector-monitor-$(date -u +%Y%m%dT%H%M%SZ).log"
```

这是可选的 /tmp 输出副本，权威实验产物仍在 DPC。

## 如何读输出和 ETA

- worker 状态和训练容器启动时记录的 NPU 数；metadata 的 running 不是持续心跳，也不代表已验证当前进程存活。
- 首轮 scheduler pool 的8个任务、完成 epoch、最后 tune NLL、checkpoint 写入距今及 pool ETA。pool.json 约每2秒更新，epochs.json/steps.jsonl 每个 epoch 完成训练和 tune 后更新。只看 last.pt 属性。
- ETA 根据本监控实际观察到的两次 epoch 时间边界外推到最多5轮。若首次观测到 epoch0且 initial.pt 已存在，可用训练初始化时刻作为0边界。恢复重写 initial.pt 时重新采样，不把旧 epoch 算成恢复后速度。早停可能缩短，导出/提交额外时间未知；不把它称为保证上界。预计时刻已超过却没有新epoch则显示待估，不显示虚假零时间。
- pool全部活跃任务有计时且无待排任务时，pool ETA取各卡剩余最大值；任一任务仍在前置校准/CPU特征分解或缺少计时就显示待估。
- 全范围独立训练条件计划120项（复用的LTV不重复计），顺序对照48阶段。只有科学门禁通过才会执行后续项；这不是等权总实验进度百分比。存在完成记录不等于监控重新校验了全部张量哈希。
- 未提交训练任务的同类完整耗时投影仅统计有相同路线/任务实测的部分，正在运行的部分未扣除，不包含LoDA统计/子空间构造、顺序对照和生成评估，不能当作全程剩余时间。
- 首seed主评和发现各52面板，共104；其中36是核心base/迁移状态面板，16是初始化/随机控制。核心首轮9×4×256=9216条预测仍保留原口径。面板计数不是逐样本实时进度，剩余成本按同目标任务已完成面板耗时每样本估计，排除bootstrap/分析，不能当作该阶段的精确墙钟ETA。
- 各scope锁定、主评、扩评、科学门禁和控制完成标记；最近未提交训练目录和最近更新的实验产物。

**整个 full 的剩余时间目前无法可靠给出单一数值。** 首8任务只是一部分；之后还有其他种子、发现/组合/迁移面板、四fold、层/分支消融、顺序对照、六任务扩展、全部正式扩评。后续生成量和条件分组、早停/科学门禁、缓存复用都影响耗时，源码没有预枚举完整的待运行面板计划。脚本明确显示全程ETA未知，不把首池完成当全实验结束。

长生成面板结束后才落盘；LoDA 的 CPU 分解也可能长时间没有新的 checkpoint。30分钟未见新产物只显示提示，不能单独判定卡死。错误需结合本次worker result/failure与网页日志，不根据旧 failure.json 自动重试、删锁或覆盖结果。
